# Idea File Handoff

Turn a reusable pattern into a specification another agent can apply in a different
environment. A popular post is one trigger, not a prerequisite.

Write the intended user/problem, inputs, desired result and invariant. Separate
policy (permissions, evidence freshness, citation and storage rules) from example
tools. Give an executable instruction block and enough structure to identify the
update loop, links and trust boundaries; omit sections the pattern does not need.

Keep machine-specific glue and private configuration out of the shareable artifact.
Link implementation examples or deeper explanation instead of making readers infer
the method from screenshots. Record the last verified scope/version where behavior
can change. Preserve open questions rather than claiming portability was tested.

When public hosting is requested, prefer a gist or repository that allows discussion
and tool-specific variants. Otherwise deliver the spec locally or in chat; writing
an idea file does not itself authorize publication or uploading private dotfiles.
